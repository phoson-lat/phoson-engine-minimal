# Plan I-128 — Feedback en vivo mientras el modelo compone la tool call

> **Issue:** [#128](https://github.com/phoson-lat/phoson-engine-minimal/issues/128) · **P1** · **S-M** (~2–2.5 h)
> **Rama:** `feat/i128-tool-composing-feedback`
> **Problema:** desde que el LLM empieza a streamear una tool call hasta que la tool empieza a
> ejecutarse, la UI está en silencio (fullscreen: pane quieto; clásico: último label del spinner).
> En `write_file` de 200 líneas o `bash` multi-línea el usuario espera sin feedback.

## Hallazgos verificados en código (afinan la propuesta original)

1. **Los deltas ya existen en 3 familias de providers:**
   - `_openai_compatible.py:488` vía `ToolCallAccumulator.feed_delta()` (OpenAI, OpenRouter, vLLM, Groq, …)
   - `anthropic.py:395` (`input_json_delta`)
   - `ollama.py:257`
   - **Gemini NO emite deltas** (un solo `ToolCallEvent` completo, `gemini.py:204`) → la brecha
     persiste solo allí; se documenta.
2. **El contrato de `phoson_llm/chats/base.py:45` ya tipa el stream como
   `(TokenEvent | ToolCallDeltaEvent | ToolCallEvent)*`** — los deltas son parte del contrato
   público; el loop del agente los descarta.
3. **`ToolCallDeltaEvent` no lleva `tool_call_id`** (solo `index`) → la identidad por `index`
   basta; el campo `tool_call_id` en el evento nuevo siempre va vacío.
4. **Subagentes:** `subagent.py:359` reenvía *todos* los eventos al callback `on_event` → el
   evento nuevo fluye sin romper nada (se verifica en tests).
5. **Fullscreen:** `render_chat()` (`fullscreen/render.py:124-131`) imprime la **activity line
   dentro del pane** (`render_activity_line(activity_text(), activity_frame())`) en cada pass.
   Es el sitio exacto para la línea de composición: reemplazo in-place gratuito (todo se
   re-renderiza por frame) y **cero líneas huérfanas** si el stream muere a medias
   (`current_turn = None` en done/error/cancel limpia todo; el path I-83 ya gestiona el resto).
6. **Clásico:** `WaitingSpinner.start()` es **idempotente** (`renderer.py:89-96`: relabel si el
   thread vive) → relabel seguro.
7. `formatting.py` ya tiene `tool_verb()` y `_card_header()` → se reutilizan (paridad de
   frontends, principio #1).

## Decisiones de diseño

- **Evento:** `AgentToolComposingEvent(index, tool_call_id, tool_name, args_chunk)` en
  `phoson_agent/models.py`, exportado en `phoson_agent/__init__.py`.
  - `args_chunk` es un **fragmento JSON crudo, opaco** — nunca `json.loads`.
  - `tool_call_id` siempre `""` (los deltas del LLM no lo llevan).
- **Emitir desde `AgentLoop._consume_llm_stream()`** (el único punto donde hoy se descarta el
  evento), con **throttle leading-edge** de ~250 ms (≤ ~4 eventos/s):
  - primer `args_chunk` no vacío del índice (siempre),
  - el nombre pasa de `""` a conocido (siempre),
  - heartbeat si hay más chunks y han pasado ≥ 250 ms desde el último emit.
  - Estado local al método (sin state en el loop entre iteraciones).
  - Pasa por `_prepare_event` (middleware) como todos los demás.
- **Fullscreen:** la línea de composición va en la **activity line del pane** (no como bloque
  efímero en `blocks`). Razón: `blocks` es histórico append-only; un bloque temporal no lo
  limpiaría ningún path si el stream falla a medias, dejando una huérfana. `CurrentTurn` gana
  `composing_tool: str`; `activity_text()` rinde `⚙ {verb}…`, `status_text()` gana
  `"Composing tool"`, y `AgentToolStartEvent` lo limpia (la card start lo reemplaza).
- **Clásico:** `case AgentToolComposingEvent()` → `start_waiting("⚙  {verb}…")` (idempotente);
  se ignora si el nombre es vacío o hay panel Live de texto abierto (ese ya es el feedback).
- **Docs:** `docs/api/phoson_agent.md` (lista + tabla de campos + notas de throttle y Gemini).

## Fases (1 commit cada una)

1. **Engine** — evento + `_consume_llm_stream` + export + tests
   (`tests/phoson_agent/test_agent_composing_unit.py`):
   - deltas → composing antes del primer `AgentToolStartEvent`, con nombre en cuanto se conoce;
   - 50 chunks rápidos → composing acotado por throttle (primer emit siempre presente);
   - stream solo texto/reasoning → cero composing;
   - error mid-composing → composing + `AgentErrorEvent`, sin crash.
2. **Fullscreen** — `CurrentTurn.composing_tool` + `on_event` + `activity_text` + `status_text`
   + `tick_activity_frame`; tests en `test_sink_unit.py` + golden ANSI en `test_e2e_tui.py`.
3. **Clásico** — dispatch + `_on_tool_composing`; tests en `test_renderer_unit.py`.
4. **Docs** — `docs/api/phoson_agent.md` + `CHANGELOG.md`; al mergear, `IMPROVEMENTS.md`.
5. **Quality gates** — `ruff format` / `ruff check` / `pyright` / `pytest` limpios.

## Riesgos

| Riesgo | Mitigación |
|---|---|
| Inundación de eventos (200 líneas ≈ cientos de deltas) | Throttle leading-edge 250 ms en el engine |
| Crash por parsear JSON parcial | `args_chunk` opaco, nunca `json.loads` |
| Línea huérfana si el stream falla/cancela a medias | La composing vive en `current_turn`, no en `blocks` |
| Estado entre iteraciones | Throttle local a `_consume_llm_stream()` |
| Middleware/subagent desconocedores del evento | Test de flujo con subagent + RetryMiddleware |
| Doble label en spinner clásico | `WaitingSpinner.start()` idempotente (verificado) |

## Criterios de aceptación (mapeados del issue)

- [ ] Test: deltas → `AgentToolComposingEvent` antes de `AgentToolStartEvent`, con nombre en
      cuanto se conoce; streams de solo texto/reasoning no emiten composing.
- [ ] Fullscreen: línea de composición visible durante la generación, reemplazada in-place
      (sin duplicados ni líneas huérfanas).
- [ ] Clásico: el label del spinner cambia al verbo de composición.
- [ ] `ruff format` / `ruff check` / `pyright` / `pytest` limpios.
