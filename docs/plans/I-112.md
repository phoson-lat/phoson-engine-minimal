# Plan I-112 — `UserWarning` de Python impreso a stderr además del warning estilizado del CLI

> **Issue:** [#112](https://github.com/phoson-lat/phoson-engine-minimal/issues/112) · **P2** · **S** (~1.5–2 h)
> **Rama:** `fix/i112-no-raw-warnings-stderr` (convención: `fix/iNNN-descripcion`)
> **Problema:** cuando un soft-fail interno dispara `warnings.warn(..., UserWarning)` (p. ej.
> el modelo no aparece en `/v1/models` de vLLM), el usuario ve **dos** salidas: el notice
> estilizado del CLI (`⚠ … — pick one with /model`) **y** el warning crudo de Python con
> archivo+línea a stderr (`.../context_window.py:136: UserWarning: …`). El ruido rompe la
> TUI y expone rutas internas.
> **Criterio de listo (del issue):** test de regresión (capfd) — ante un fallo de
> resolución de context window, **nada** se escribe en stderr y el notice estilizado
> aparece una sola vez.

## Hallazgos verificados en código (afinan la propuesta original del issue)

1. **El fullscreen YA lo resuelve (parcialmente):** `PhosonApp.run_async()`
   (`fullscreen/app.py:1231-1245`) hace `logging.getLogger().handlers.append(NullHandler())`
   + `propagate=False` + `logging.captureWarnings(True)` → los `warnings.warn` dentro del
   alt-screen van a logging (NullHandler → nada). Test existente:
   `tests/phoson_cli/fullscreen/test_fullscreen_shell_unit.py:838-876`.
   **No tocar ese bloque** — solo actualizar su comentario (dice "so classic-mode
   warnings are unaffected", que dejaría de ser el motivo real tras este fix).
2. **El bug vivo es el modo clásico (+ one-shot):** `main()` (`__main__.py:338`) **no**
   instala ningún hook de warnings → el hook default `warnings.showwarning` imprime el
   warning crudo a stderr. En `--classic`, el notice estilizado **no** viene de logging:
   `Renderer.print_warn()` (`renderer.py:589-591`) imprime `render_notice("warn", …)`
   (`formatting.py:272-275`, `  ⚠ {message}` en `theme.warn`) a **stdout** por consola
   rich. Por eso en clásico se ven las dos salidas: notice (stdout) + crudo (stderr).
3. **Hay un segundo canal crudo:** los módulos emiten `logger.warning` en los mismos
   soft-fails sin handlers configurados → `logging.lastResort` imprime
   `WARNING:phoson_agent…: <msg>` a stderr. Ej.: `_resolve_ollama`/`_resolve_openrouter`/
   `_resolve_vllm` (`context_window.py:170-176, 254-260, 301-307`) llaman a
   `warnings.warn` **y** `logger.warning` en el mismo except → hoy son **dos** líneas
   crudas + el notice.
4. **Inventario real de `warnings.warn`** (más amplio que los 7 citados en
   IMPROVEMENTS.md):
   - `phoson_agent/plugins/context_window.py`: 6 (líneas 163, 170, 199, 254, 301, 315)
   - `phoson_agent/tool.py:168` — warn a developer (kw-only no inyectado en `@tool`)
   - `phoson_llm/pricing.py:155` — **`UnknownModelWarning`** (subclase de UserWarning;
     el mensaje *recomienda* al usuario `filterwarnings` — advice que este fix obsoleta)
   - `phoson_cli/model_selector.py:62` — fallback de model listing
   - `phoson_cli/config.py:149, 233, 559` — int/float env inválido, `compact_mode` inválido
   - `phoson_cli/theme.py:300` — theme desconocido
   - `phoson_cli/terminal_theme.py:232` — OSC 11 probe falló
   - `phoson_cli/session_utils.py:172` — MCP init falló
5. **`logger.warning`/`_LOGGER.warning`** (mismo problema de lastResort):
   `context_window.py:175, 259, 306` (duplican el warn del mismo except),
   `controller.py:327, 411, 814`, `session_utils.py:191`, `permissions_store.py:67`,
   `skills.py:197, 319`, `phoson_llm/utils.py:101, 109`, `agent.py:277`.
   Ninguno coexiste con un `warnings.warn` en el mismo path **salvo** los 3 de
   `context_window.py` → esos 3 se eliminan (dedup); el resto se cubre con el handler
   de logging del hook.
6. **El "notice estilizado" del flujo de error NO es el warning:** `⚠ not_found — model
   id may be wrong — pick one with /model` es un hint de `AgentErrorEvent`
   (`_ERROR_HINTS`, `formatting.py:615`) que llega con el fallo del request al provider.
   El notice que acompaña hoy al warn de context window **es** el warning crudo. Con el
   hook, el texto del warn (compacto, sin rutas) pasa a ser el notice estilizado → se
   cumple la experiencia del issue: una sola línea `⚠ …`, y el hint de error si además
   falla el request.
7. **`_LOGGER` de `controller.py` no se usa en path activo** (grep vacío) → no hay
   dependencia de handlers existentes.
8. **`basicConfig` solo con `PHOSON_SUBAGENT_DEBUG=1`** (`subagent.py:56-58`, debug de
   tests) → el guard del hook debe ser defensivo si el root ya tiene handlers, pero en
   prod no hay colisión.

## Decisión de diseño (verificada empíricamente)

**Canal único = el notice estilizado.** Dos hooks en el entrypoint del CLI, no migrar
`warnings.warn` a `logger.warning`:

- **Hook 1 — `warnings.showwarning` → notice.** Cubre los 14 `warnings.warn` actuales
  (nuestro código + el repro del issue, que es el else-branch "modelo no listado").
- **Hook 2 — root `logging.Handler` → notice.** Los `logger.warning` sin handler caen a
  `logging.lastResort` → stderr crudo (`WARNING:phoson_…`). El handler enruta
  `phoson_*` `WARNING+` al mismo notice.
- El engine (`phoson_agent`) es librería importable: el hook vive en el CLI y no
  contamina el uso programático.
- **Fullscreen:** probe de CPython confirma que `logging.captureWarnings(True)` **ya**
  reemplaza `showwarning` (y lo restaura al salir del alt-screen), así que el hook se
  compone con el fullscreen **sin guardar extra**. Aun así, `run_async` marca un flag
  (`set_fullscreen_active`) para que ambos hooks sean no-op dentro del alt-screen (el
  TUI no puede recibir prints fuera de su buffer); el par `NullHandler`+`captureWarnings`
  existente se queda intacto.

### Componente nuevo: `phoson_cli/warnings_hook.py`

```python
"""Route warnings + phoson logging through the CLI notice channel (I-112)."""

# Printer mutable: default imprime plano a stdout (one-shot); el REPL clásico lo
# sobreescribe con renderer.print_warn (paridad visual + theme en vivo).
notice_printer: Callable[[str], None] = _default_notice_printer  # print("  ⚠ {line}")

_fullscreen_active = False
def set_fullscreen_active(active: bool) -> None: ...

def install() -> Callable[[], None]:
    """Reemplaza showwarning + añade _PhosonNoticeHandler al root.
    Devuelve restore() idempotente (SystemExit dispara finally → garantizado)."""

def _hooked_showwarning(message, category, filename, lineno, file=None, line=None):
    if _fullscreen_active: return            # el alt-screen lo gestiona
    notice_printer(f"{category.__name__}: {' '.join(str(message).split())}")

class _PhosonNoticeHandler(logging.Handler):
    """WARNING+ de loggers phoson_* → notice_printer (evita lastResort a stderr)."""
    # emit(): no-op si _fullscreen_active; si record.name no startswith
    # ("phoson_agent","phoson_cli","phoson_llm","phoson_plugin") o <WARNING → skip.
    # → notice_printer(one_line(record.getMessage()))
```

**Formato del notice:** `  ⚠ {CategoryName}: {message}` (p. ej.
`  ⚠ UserWarning: vLLM /v1/models response did not include 'google/...'…`).
Prefijo `  ⚠ ` idéntico a `render_notice("warn", …)` y a los existentes
(`commands.py:511`, `model_picker.py:192`). El `CategoryName` conserva la
distinguibilidad de Python (`UserWarning:`, `UnknownModelWarning:`, …).

- **Printer default:** `print(f"  ⚠ {line}")` → **stdout** (nunca stderr: el criterio
  del issue lo exige; los warnings son avisos, no errores).
- **Printer con theme (clásico):** en `PhosonRepl.__init__` (tras el `Renderer`):
  `warnings_hook.notice_printer = self.renderer.print_warn` → paridad visual exacta y
  theme en vivo (el `apply_theme` re-puntea `renderer.theme`; el closure lo lee en
  llamada). (Principio 1 de IMPROVEMENTS.md: mismo formato en ambos frontends.)
- **One-shot:** usa el printer default (no hay tema/REPL; la salida es script-friendly).

### `main()` (`phoson_cli/__main__.py`)

```python
def main() -> None:
    restore = warnings_hook.install()      # ANTES de parse_args/load_config:
    try:                                   # cubre warns de config, theme, etc.
        _run_cli()                         # cuerpo actual de main() refactorizado
    finally:
        restore()
```

- `restore()` devuelve `warnings.showwarning` al original y retira el
  `_PhosonNoticeHandler` del root. `SystemExit` (los `sys.exit` de main) **sí**
  dispara `finally` → restore garantizado en todos los paths.
- **No `basicConfig`** en el CLI: evita doble-impresión con `lastResort` y no pisa
  setups de tests.

### Dedup en `context_window.py` (verificado: los except emiten warn **y** log)

En los 3 except (Ollama `:170`, OpenRouter `:254`, vLLM `:301`) se emite
`warnings.warn` **y** `logger.warning` del mismo fallo → con los 2 hooks serían **2**
notices. **Quitar el `warnings.warn` y conservar el `logger.warning`** (el log es el
canal único de esos 3; el `warnings.warn` se queda solo en el else-branch "modelo no
listado" `:315` y en los warns de parse `:163`/`:199`). **No** eliminar el
`logger.warning`: dos tests lo exigen por trazabilidad (issue #23):
`test_unreachable_server_falls_back_to_default` y
`test_ollama_fallback_logs_warning_for_traceability` (ambos asientan sobre `caplog`).

Resultado: else-branch → 1 notice (hook); except → 1 notice (handler de logging, el log
sigue siendo la señal de trazabilidad). Sin dobles, sin stderr crudo.

## Riesgos y mitigaciones

| Riesgo | Mitigación |
|---|---|
| `sys.exit` dentro de `main()` salte el restore | `SystemExit` dispara `finally` (Python estándar) → restore garantizado. Test 6 cubre idempotencia. |
| Tests que asumen el `showwarning` default | Solo `test_fullscreen_shell_unit.py:838-876` lo toca (delegación ya contemplada, test llama a `run_async` sin `main()`). El resto usa `pytest.warns` (firing, no emisor). |
| Doble-impresión `lastResort` (logger.warning crudo) | El `_CliNoticeLogHandler` en el root captura WARNING+ de `phoson_*` → `lastResort` no se usa para esos. Los 3 duplicados de `context_window.py` se eliminan. |
| El fullscreen recibe prints fuera del buffer | Guards dobles: `captureWarnings()` activo → el hook delega; `propagate=False` + NullHandler (ya existentes en `run_async`) → el handler de logging no emite dentro del alt-screen. |
| Warnings disparados antes del hook | `install()` va al inicio de `main()`, antes de `parse_args`/`load_config` → cubre todos los warns del CLI (verificado: no hay warns en import-time del path CLI). |
| Warnings de librerías (httpx, …) van ahora al notice | Deseable: un solo canal para el usuario. El `CategoryName` en el notice conserva la distinguibilidad. |
| `PHOSON_SUBAGENT_DEBUG` + hook | El `basicConfig(DEBUG)` de `subagent.py` aún se aplica si el root no tiene handlers; con el hook instalado (prod) sí hay → los debug no se imprimen a stdout, el handler (WARNING) no los muestra. Comportamiento de prod inalterado; el env de debug se documenta en el PR. |
| `notice_printer` mutable (estado global) | Es un atributo de módulo documentado con un solo propósito (inyección del printer con theme); el test 1–6 lo resetean. Alternativa (callback inyectado) se descarta por la firma de `showwarning` (sin contexto). |
| Mensaje de warn con rutas internas | Los mensajes de `warnings.warn` de nuestro código **no** incluyen rutas (verificado en el inventario); la línea cruda `archivo:linea:` venía solo del showwarning default, que ya no se usa. |
